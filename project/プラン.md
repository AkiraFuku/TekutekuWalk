# PG4 課題プラン：STLコンテナを使ったステージ内チェックポイント管理システム

## 1. 課題の目的と要件整理（スライド準拠）

### ゲーム内の場面（題材4：ステージ内チェックポイント）
ステージ各所のチェックポイントの通過状況を記録し、**死亡時のリスポーン地点**や**ファストトラベル先**を管理するシステムを構築する。
プレイヤー自身の移動処理などのゲーム本編ロジックには組み込まず、過去の `PG4_01_02`（武器システム `WeaponContainer`）と同様に、以下の3点セットで実装する：
1. **チェックポイント管理クラス (`CheckpointContainer.h`)**
2. **動作確認用 ImGui デバッグウィンドウ (`GameScene.cpp` / `GameScene.h`)**
3. **単体テスト専用 `Main` (`standalone_assignment/CheckpointMain.cpp`)**

### 必要な操作（必須要件）
1. **未到達地点の到達フラグ更新**
   - チェックポイントに到達した際、未到達（`isReached == false`）であれば到達済み（`isReached == true`）に更新する。
2. **最後に通過した有効チェックポイントの取得**
   - プレイヤー死亡時のリスポーン処理などのため、最後に通過（有効化）したチェックポイントの情報を即座に特定・取得する。
3. **地点 ID を指定した座標情報の検索**
   - ファストトラベルやリスポーン移動のため、地点 ID をキーとして対象チェックポイントの座標 `(x, y, z)` を検索・取得する。

## 2. コンテナを選ぶ4つの判断基準と選定理由

講義スライドの「コンテナを選ぶ4つの判断基準」および「主要コンテナの計算量と特徴」に基づき、以下のコンテナを選定する。

| 判断基準 | チェックポイント管理における要件 | 採用する設計・コンテナ |
| :--- | :--- | :--- |
| **1. 出入口の制限** | 任意の地点 ID の状態更新・座標参照に加え、最後に通過した地点の即時取得が必要 | 任意キー参照に `std::map`、通過順序（最新地点）の履歴管理に `std::stack` を併用 |
| **2. 検索の手段** | 地点 ID を指定して座標情報や到達状態を高速に検索する必要がある | **`std::map<CheckpointId, CheckpointData>`**（検索・挿入ともに計算量 $O(\log N)$） |
| **3. 一意性の要求** | 各地点 ID はステージ内で一意（重複なし）。同じ地点を再通過しても登録データは1つに限定 | `std::map` のキー一意性により保証 |
| **4. 順序の重要度** | ①ファストトラベル一覧では「地点 ID 順（自動整列）」が望ましい<br>②任意の順序で解放される場合、「通過順序の保持（最新リスポーン地点の特定）」も重要 | ① `std::map` で ID 順に自動整列<br>② **`std::stack<CheckpointId>`**（LIFO: 後入れ先出し、末尾操作 $O(1)$）で通過順を保持し、最新地点を $O(1)$ で即時特定 |

> **選定のまとめ**
> - **メイン管理 (`std::map`)**: 地点 ID からの高速な座標検索 ($O(\log N)$) と未到達フラグ更新、およびファストトラベル一覧の自動整列を担当。
> - **通過順序・最新地点管理 (`std::stack`)**: 任意の順序でチェックポイントを通過した場合でも、最後に通過した有効チェックポイントを $O(1)$ (`top()`) で即座に特定する役割を担当。

## 4. データ構造とクラス設計 (`CheckpointContainer`)

### 4.1 地点 ID とデータ構造
```cpp
// チェックポイントIDの定義（離れたID値でも std::map なら効率的に管理可能）
enum class CheckpointId {
    Entrance    = 100, // ステージ入口
    Valley      = 200, // 渓谷の吊り橋
    Ruins       = 300, // 古代遺跡前
    MidBossRoom = 400, // 中ボス部屋前
    Summit      = 500, // 山頂（ボス前）
};

// 3次元座標構造体
struct CheckpointPos {
    float x = 0.0f;
    float y = 0.0f;
    float z = 0.0f;
};

// チェックポイント情報構造体
struct CheckpointData {
    std::string name;           // 地点名
    CheckpointPos position;     // 座標情報 (x, y, z)
    bool isReached = false;     // 到達フラグ（false: 未到達, true: 到達済み）
};
```

### 4.2 `CheckpointContainer` クラスの主なメソッド

| メソッド名 | 役割・対応する課題要件 | 計算量 |
| :--- | :--- | :---: |
| `RegisterCheckpoint(id, name, pos)` | ステージ初期化時にチェックポイント（未到達状態 `isReached = false`）を `std::map` に登録 | $O(\log N)$ |
| `ReachCheckpoint(id)` | **【要件1】未到達地点の到達フラグ更新**。<br>`find(id)` で検索し、`isReached = true` に更新。同時に通過履歴 `std::stack` に `push(id)` して最終通過地点を更新（戻り値: `1`=初回到達, `2`=再通過, `0`=未登録ID） | $O(\log N)$ |
| `GetLastCheckpoint()` | **【要件2】最後に通過した有効チェックポイントの取得**。<br>`std::stack::top()` から最後に通過した ID を $O(1)$ で特定し、リスポーン座標・情報を返す | $O(1)$ / $O(\log N)$ |
| `FindCheckpointPosition(id, outPos)` | **【要件3】地点 ID を指定した座標情報の検索**。<br>`std::map::find(id)` を用いて指定 ID の座標を検索する | $O(\log N)$ |
| `UndoLastCheckpoint()` | 通過履歴スタック (`std::stack::pop`) を使い、最後に通過した地点を1つ前のチェックポイントへ巻き戻す | $O(1)$ |
| `ResetAll()` | 全チェックポイントを未到達状態にリセットし、通過履歴スタックを空にする | $O(N)$ |

## 5. 動作確認用 ImGui の設計 (`GameScene.cpp`)

`PG4_01_02` の武器インベントリ ImGui と同様に、`ImGui::Begin("Stage Checkpoints (STL Assignment)")` ウィンドウを作成し、以下の4セクションを配置する。

### セクション1：最後に通過した有効チェックポイント（リスポーン地点表示）
- 現在有効な最終通過チェックポイント（`std::stack::top()`）の **ID・地点名・リスポーン座標 `(x, y, z)`** をハイライト表示する（未通過時は `(None - Initial Spawn)` と表示）。
- **`[ Respawn at Last Checkpoint ]` ボタン**: 押下すると最後に通過したチェックポイントの座標へリスポーンするログを出力。
- **`[ Undo Last Pass (stack::pop) ]` ボタン**: 通過履歴スタックを1つ戻し、直前のチェックポイントへ切り替わることを確認できる。

### セクション2：ステージ内チェックポイント一覧 & ファストトラベル (`std::map`)
- `std::map` に登録された全チェックポイントを ID 順に表示（`[Reached]` は緑色、`[Unreached]` はグレー表示）。
- 各行に以下のボタンを配置：
  - **`[ Pass / Reach ]` ボタン**: その地点を通過（未到達なら `isReached = true` に更新し、最終通過地点に設定）。任意の順序でクリックして解放順テストが可能。
  - **`[ Fast Travel ]` ボタン**: 到達済み (`isReached == true`) の場合のみ有効。`FindCheckpointPosition(id)` で座標を取得してファストトラベルを実行。

### セクション3：地点 ID 指定による座標検索・個別操作 (`std::map::find`)
- コンボボックス（または ID 入力欄）でチェックポイント ID（存在しないダミー ID `999` も選択可能）を選択。
- **`[ Search Position by ID (find) ]` ボタン**: 指定した地点 ID の座標 `(x, y, z)` と到達状況を `std::map::find` で検索し、結果をログに出力。
- **`[ Reach Selected ]` ボタン**: 選択中の ID の到達フラグを更新。
- **`[ Reset All Checkpoints ]` ボタン**: 全地点を未到達状態にリセットして最初からテストし直せる。

### セクション4：操作ログ (`[ Action Logs ]`)
- 実行した操作（「ID: 300 Ruins に初到達！フラグを更新しました」「ID: 200 の座標 (50, 10, 0) を検索しました」など）を時系列（最新順）でスクロール表示する。
- **`[ Clear Logs ]` ボタン**でログ消去可能。

## 6. テスト専用 `Main` (`CheckpointMain.cpp`) の検証シナリオ

過去の `WeaponContainerMain.cpp` と同様に、ステップごとのコンソール出力で要件動作がひと目で分かるデモシナリオを実装する。

- **[Step 1] ステージ内チェックポイントの初期登録**
  - ステージ内の5つのチェックポイント（ID: 100〜500）を未到達状態 (`isReached = false`) で登録し、一覧を表示する。
- **[Step 2] チェックポイント未通過状態でのリスポーン確認**
  - まだ1つも通過していない状態で `GetLastCheckpoint()` を呼び出し、安全に未通過判定されることを確認する。
- **[Step 3] 未到達地点の到達フラグ更新（順番通り＆任意の順序での通過）**
  - `Entrance (ID: 100)` → `Ruins (ID: 300)`（※200を飛ばして任意の順序で解放）の順に通過し、`isReached` フラグが `false -> true` に更新されることを確認する。
- **[Step 4] 最後に通過した有効チェックポイントの取得（死亡時リスポーン）**
  - `GetLastCheckpoint()` で最後に通過したチェックポイントの ID・地点名・リスポーン座標 `(x, y, z)` が即座に取得できることを確認する。
  - その後 `Valley (ID: 200)` を通過すると、ID の大小に関係なく「最後に通過した `Valley (ID: 200)`」が最新リスポーン地点になることを確認する。
- **[Step 5] 地点 ID を指定した座標情報の検索（`std::map::find` とファストトラベル検証）**
  - 到達済みの地点 ID（`ID: 100`）、未到達の地点 ID（`ID: 400`）、存在しない地点 ID（`ID: 999`）を検索し、座標取得とファストトラベル可否判定を確認する。
- **[Step 6] 通過履歴の巻き戻し確認（`std::stack::pop` の活用デモ）**
  - スタックに記録された通過順序を確認し、1つ前のチェックポイントへ戻る操作も実演する。
